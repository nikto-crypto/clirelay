## Information sources consulted

- `BUILD_PROMPT.md` — the verbatim task, including its list of known traps.
- `~/clirelay-oracle/API_SURFACE.json` — the public API surface (names, kinds,
  signatures, enum members, deprecated-attribute warnings). Generated by the
  study's own `~/clirelay-oracle/tools/api_surface.py`, which I read to learn the
  JSON schema.
- The oracle itself, used **only as a black box**: imported from
  `~/clirelay-oracle` on `sys.path`, driven through its public API, with results
  compared against clirelay. No source, bytecode, docstrings, or introspection.
- Python standard library documentation (my own knowledge), for stdlib modules.

I did **not** consult: Click's source, tests, docs, examples, repository, the
Pallets documentation site, PyPI package contents, GitHub, mirrors, or any web
page quoting Click. No web searches about Click were run.

## Shell completion scripts

The four shell source scripts (bash/zsh/fish/powershell) must match the oracle
byte for byte, which `BUILD_PROMPT.md` explicitly permits. They are reproduced
from the oracle's `source()` output and live in the single module
`src/clirelay/_completion_scripts.py`. The similarity check should treat that one
module separately from the rest of the library.
